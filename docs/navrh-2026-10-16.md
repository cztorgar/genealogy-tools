*16. 10. 2026*

## 1. Výchozí stav

Geografické těžiště: Chlumecko, Novobydžovsko, Hradecko, Pardubicko → **SOA Zámrsk**.
Vedlejší větve: střední Čechy (Liteň, Nosetín → **SOA Praha**), `Gerlachov` (pravděpodobně Slovensko).

Nemáš DNA test a na stromu pracuješ sám. Strom je dnes převážně **opsaný z cizích stromů**, ne doložený prameny.
Největší přidaná hodnota workbenche proto není „víc jmen“, ale **ověření stávajících faktů v matrikách
a doplnění citací**.

## 2. Jak to s AI dělají jiní

**Tři převládající vzory:**

1. **Strukturovaná databáze + MCP server.** Nejživější ekosystém je kolem **Gramps Web** (REST API):
   - [cabout-me/gramps-mcp](https://github.com/cabout-me/gramps-mcp) — Python, čtení i zápis, 45★
   - [Scormave/gramps-web-mcp](https://github.com/Scormave/gramps-web-mcp) — .NET, ~30 nástrojů, read-only režim;
     do v2.3.1 `update_*` tiše zahazovaly data
   - [gramps-ez-mcp](https://github.com/dsblank/gramps-ez-mcp) — nad lokální desktop DB
   - webtrees má [Jefferson49/webtrees-API](https://github.com/Jefferson49/webtrees-API) s MCP, OAuth a zápisy
     přes moderaci (nejlépe navržený model zápisu)
   - nad holým GEDCOM: [airy10/GedcomMCP](https://github.com/airy10/GedcomMCP),
     [vaelen/gedcom-skills](https://github.com/vaelen/gedcom-skills)
   - nad MyHeritage FTB pouze read-only [mouchar/ftb-mcp](https://github.com/mouchar/ftb-mcp) (autor zřejmě Čech)
2. **Výzkum jako soubory v gitu (Obsidian/Markdown + agent).**
   - [mattprusak/autoresearch-genealogy](https://github.com/mattprusak/autoresearch-genealogy) (1 183★) —
     Claude Code + Obsidian vault s YAML, audity citací a křížových odkazů
   - [sliday/genealogy-research](https://github.com/sliday/genealogy-research) — odděluje doslovný přepis /
     transliteraci / překlad / interpretaci, vede PROCESS.md včetně negativních výsledků, změny stromu navrhuje
     jako patch k revizi
   - [emaynard/claude-family-history-research-skill](https://github.com/emaynard/claude-family-history-research-skill) —
     plánování podle Genealogical Proof Standard
3. **Metodické MCP / prompty**
   - [igormel81/genealogy-mcp](https://github.com/igormel81/genealogy-mcp) — kalendáře, svátky, varianty jmen,
     kontrola shody, audit stromu
   - [DigitalArchivst/Open-Genealogy](https://github.com/DigitalArchivst/Open-Genealogy) — GPS prompty

**Přepis rukopisů:**

- Osvědčený postup je dvoufázový:
  1. HTR dá řádkový draft:
     - [Transkribus Czech Handwriting M1](https://www.transkribus.org/models/transkribus-czech-handwriting-m1)
       (CZ/DE/LA, CER ~6,6 %) nebo Text Titan II
     - nebo [PERO OCR](https://pero.fit.vutbr.cz/) z VUT — česká alternativa, umí i kurrent
  2. LLM pak rozvine zkratky, přeloží a vytáhne strukturu.
  3. Na závěr kontrola člověkem proti snímku.
- Samotné vision LLM jsou na anglických rukopisech už lepší než Transkribus (Gemini 3 Pro ~1,7 % CER,
  Claude Opus 4.5 ~4,3 %, [benchmark](https://generativehistory.substack.com/p/gemini-3-solves-handwriting-recognition)).
  Typicky ale „normalizují“ jména, vynechávají řádky a vymýšlejí věrohodná data.
- Na českých, latinských a kurrentových matrikách **neexistuje žádný změřený test**.

**Český analog:**

- [lioilsources/genealogy-matriky](https://github.com/lioilsources/genealogy-matriky) — pipeline: stažení
  z eBadatelny → OCR → extrakce LLM do JSONL → SQLite s pravděpodobnostním párováním osob → strom s proklikem
  na sken.
- Stahovače pro jednotlivé portály:
  - Porta fontium: [Testatost](https://github.com/Testatost/Porta-fontium-Downloader)
  - Acta Publica: [lffelmann](https://github.com/lffelmann/actapublica-image-downloader),
    [haxny](https://github.com/haxny/matrika-mza-sync)

## 3. České prameny — co z toho plyne technicky

- Matriky jsou online u všech SOA, **ale jen jako obrázky bez jmenného indexu**.
  - Výjimky se jmenným indexem: policejní přihlášky Praha 1850–1914 (NA), databáze padlých VÚA, holocaust.cz.
  - FamilySearch má obrázky části SOA a jen malé indexy.
- **API ani IIIF nemá nikdo.**
  - [ARON Zámrsk](https://aron.vychodoceskearchivy.cz/) má nedokumentovaný JSON backend → technicky nejlépe
    přístupný a zároveň **tvůj hlavní archiv**.
  - Porta fontium, Acta Publica a Opava jedou na DZI dlaždicích.
- **Anti-bot ochrany:**
  - MZA blokuje IP adresy (v letech 2021–22 zablokovala 7 uživatelů)
  - Opava (Radware)
  - Litoměřice (challenge)
  - Plzeň (403)
  - ⇒ jen **stahování na vyžádání rychlostí člověka a lokální cache**, žádný hromadný mirror. Podmínky užití
    portálů je potřeba přečíst před implementací.
- **Kramerius** má funkční veřejné REST API v7 (schematismy, adresáře, Verlustlisten, noviny).
- **Místopis:**
  - Historický lexikon obcí je jen PDF/XLS
  - pro párování se hodí Wikidata, RÚIAN a `place_history` z igormel81
- **Lhůty zveřejnění matrik:** narození 100 let, sňatky a úmrtí 75 let.
- **MyHeritage** má pro ČR index Church Books (~112 tis. záznamů) a **index sčítání lidu 1921 (5,6 mil.)**
  — to je jeho jediná skutečně česká přidaná hodnota.

## 4. MyHeritage: zůstat, přejít, nebo vlastní?

**Co MyHeritage dává:**

- Smart/Record Matches proti cizím stromům a Geni
- index sčítání 1921
- AI Scribe
- hezké sdílení s rodinou

**Co neumí:**

- veřejné API (Family Graph API je mrtvé)
- export bez ztrát — média jsou jen expirující odkazy, Smart Matches se neexportují
- import zpět bez ztrát — GEDCOM import založí **nový strom**, neslučuje [neověřeno, ale konzistentně
  hlášeno], a ztratí se potvrzené shody
- DNA, které by tě drželo, nemáš

**Alternativní služby:**

- Ancestry je pro ČR slabé.
- FamilySearch a Geni jsou jeden sdílený světový strom, takže se nehodí jako master.
- WikiTree neumí import.

**Vlastní řešení — Gramps Web (Docker):**

- REST API, média lokálně, role, soukromí žijících osob
- import GEDCOM s náhledem
- synchronizace s Gramps desktop
- 3+ hotové MCP servery

**Doporučení: hybrid s jasným směrem dat.**

```
          ┌────────────── MASTER ──────────────┐
          │  Gramps Web (Docker)               │◄── MCP (agent, nejdřív read-only)
          │  osoby, rodiny, místa, zdroje,     │
          │  citace, média                     │──► noční export Gramps XML → git
          └──────────────▲─────────────────────┘
                         │ ruční / agentem navržené změny (patch k revizi)
MyHeritage ──────────────┘  jen jako zdroj NÁPOVĚD (Smart Matches, sčítání 1921)
  (zmrazený strom, do MyHeritage se nezapisuje zpět — volitelně občasný jednosměrný „mirror“)
```

- **Master** je Gramps Web.
- **MyHeritage** předplatné nech doběhnout. Za dobu, co ho máš, vytěž Smart Matches a sčítání 1921 (každá
  nápověda = úkol k ověření v matrice, ne fakt). Pak rozhodni, zda stačí Basic.
  - Basic má limit 250 osob, strom má 395 → zmrazený strom by zůstal jen pro čtení. **Ověřit.**
- **Čistě vlastní databáze / textové soubory bez Gramps** nedoporučuji. Gramps řeší datový model (datace,
  hierarchie míst, citace, soukromí), který by sis jinak psal sám, a MCP vrstva už existuje.
  - Textové poznámky ale ano — jako výzkumný deník vedle databáze (viz níže).

## 5. Návrh workbenche

### Vrstvy

| Vrstva | Co | Nástroj |
|---|---|---|
| **Data** | strukturovaný strom, master | Gramps Web v Dockeru (lokálně, nebo na MAYA za ZeroTier — viz rozhodnutí) |
| **Verzování** | noční export Gramps XML (nekomprimovaný) do gitu → diff každé změny | cron + git ([vzor](https://github.com/dgm9704/tree)) |
| **Výzkumný deník** | otázky, plán, log hledání vč. „nic nenalezeno“, přepisy (doslovně / normalizovaně / překlad / interpretace odděleně), závěry | Markdown v tomto repu, struktura inspirovaná sliday + autoresearch |
| **Archivní cache** | stažené snímky stran matrik + metadata citace (archiv, fond, matrika/inv. č., folio, snímek, URL, datum) | vlastní malý nástroj, cache na disku |
| **Čtení písma** | HTR draft → LLM extrakce → lidská kontrola | PERO OCR / Transkribus M1, Claude vision |
| **Agent** | Claude Code + MCP | viz níže |

### MCP / nástroje pro agenta

1. **gramps-mcp** (cabout-me, Python) proti Gramps Web.
   - **Začít v read-only režimu.** Zápisy později, jen jako návrh, který potvrdíš.
2. **igormel81/genealogy-mcp.** Z něj kalendáře, svátky, varianty jmen (včetně německých), `check_match`,
   `audit_tree`, `kinship`, `place_history`. Jeho katalog zdrojů pro ČR je chudý.
3. **Vlastní `czech-archives` MCP** — jediná podstatná věc, kterou je potřeba napsat:
   - `find_register(obec, rok, typ)` → která farnost, která matrika a kde (začít ARON Zámrsk + eBadatelna)
   - `fetch_page(matrika, snímek)` → stáhne do cache, šetrně, s rate limitem
   - `cite(…)` → jednotná citace podle české praxe
   - Kramerius search (schematismy kvůli farnostem, adresáře, noviny)
   - inspirace a licence: lioilsources/genealogy-matriky
4. **Skills / prompty:**
   - research plan podle GPS
   - šablona citace české matriky
   - pravidlo „jmenovec ≠ předek“ (dva nezávislé fakty navíc)
   - workflow přepisu

### Pravidla workbenche

- Nic nejde do masteru bez citace pramene. Cizí strom nebo Smart Match je jen **nápověda**.
- AI přepis je **draft**. Fakt se zapíše až po kontrole proti snímku, se snímkem v citaci.
- Agent do Gramps nezapisuje přímo. Navrhne změnu a ty ji potvrdíš.
- Žijící osoby se do LLM neposílají, pokud to nejde jinak (Gramps privacy flag, read-only MCP s filtrem).
- Archivní portály jen rychlostí člověka a na vyžádání.

## 6. Postup po etapách

| Etapa | Obsah | Výsledek |
|---|---|---|

## 7. Rozhodnutí pro tebe

1. **Kde poběží Gramps Web:** lokálně na notebooku (jednodušší, žádná data venku), nebo na MAYA
   (dostupné odkudkoli přes ZT, zálohy restic, možnost pozvat rodinu)?
2. **MyHeritage:** souhlas se „zmrazením“ jako zdroje nápověd (bez zpětného zápisu)?
3. **Pilotní linie:** kterou větev ověřovat jako první?
4. **HTR:** Transkribus (cloud, kredity) vs. PERO OCR (VUT, zdarma) vs. jen Claude vision na pilotu a porovnat?
